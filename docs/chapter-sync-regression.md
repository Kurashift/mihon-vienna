# 第三批：章节刷新完整提交

章节刷新把新增、修改和删除放进同一次数据库事务。任一步写入失败或在提交前取消，整批撤回；不把数据库失败当作正常新增零条。更新已有章节只写来源字段，保留稳定 ID、进度、历史、已读、书签、译名、标记和自定义排序。

下载篇目需要改名时，先记录已完成的文件改名。改名或数据库事务失败，按相反顺序撤回已完成的改名，并同步缓存。如果文件已经无法撤回，保留文件，在原错误中附上具体改名失败信息；不删除文件来恢复一致性。暂时返回空目录的本地源保护保留，正常新增和已确认删除仍会生效。

没有新增菜单或加载提示。正常刷新仍使用现有入口。本批只增加数据库操作语句，不升级数据库结构，也不合并全库重复记录。条漫显示和阅读规则不作调整。

## 手动回归

1. 用文件管理器在本地漫画目录准备一部只有少量篇目的测试作品副本，打开其详情。后续操作只在这份副本上进行。
2. 阅读其中一个篇目到中间，返回详情，为该篇目设置书签；单选该篇目后，从底部操作栏“编辑译名”保存一个测试译名。预期进度、书签和译名均显示正常。
3. 向测试作品目录加入一个新的篇目文件，从详情下拉刷新。预期新增篇目出现，原有篇目的进度、书签、译名和手动排序保留。
4. 再刷新一次，返回主页并从最近任务划掉应用，再重新打开测试作品。预期不多出重复篇目，原有状态与计数不变。
5. 如需验移动、目录改名或删除，只使用测试副本及已有操作入口。刷新后核对新增或删除与实际文件一致，未操作的篇目状态保持；不要用主库制造失败。下载改名的中途失败和补偿由自动测试完成。

正常新增不出现、真实删除后仍有残留、重复篇目、书签或译名丢失、进度重置、下载图标与文件不符，以及返回后计数未更新均算回归。

## 自动验证与边界

Kotlin 测试覆盖一次事务提交、删除/新增/更新阶段失败、取消回滚、重复输入、暂时空扫描与确认空目录、已有记录保留用户字段、多个文件部分改名成功、缓存失败、目标冲突与无法补偿时保留文件。

scripts/verify_chapter_sync.py 使用真实 SQLite 执行仓库的 SQL，核对事务回滚、删除级联与用户字段保留，并加入 CI。大库场景包含 3,002 部作品、14,403 个篇目；一次事务分别新增、删除和修改 1,201 个篇目，核对未涉及作品、稳定 ID、历史和标记。它验证数据一致性，不代表手机上的扫描或刷新速度。

真实手机的文件提供器、刷新联动和下载文件识别仍待用户操作验收。测试不要求清数据、撤销权限、重建本地库或制造真实文件损坏。原位安装包只在用户另行要求后准备，本批不升版本或发布。
