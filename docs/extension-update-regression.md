# 扩展安装与更新回归

## 改了什么

核对上游正式版 v0.21.3（2026-10-25 发布）后，只适配扩展匹配、下载取消与文件替换。没有迁移上游的整套扩展状态模型或依赖注入。

以前多个仓库提供同包名扩展时，更新检查取第一条，下载可能取最后一条；现在只从与已安装扩展签名匹配的仓库选择最高版本，后台通知使用相同规则。下载完成后还检查实际 APK 的包名、版本和仓库签名，检查失败不会进入安装器。

一个扩展含多个图源时，列表仍分开显示原有图源名，但保留真实安装包名，共用该扩展的安装进度和取消操作。

以前取消任务可能不能打断网络读取，同包名重试还共用下载文件和回调编号；现在每次安装使用独立文件与编号，取消会中断网络，旧任务结束和旧安装回调不能改变新任务。失败保留原有错误按钮，可以重试。系统已经确认安装或 Shizuku 已提交的任务由系统完成，不能承诺在提交之后撤销。

以前私有扩展更新先删除旧文件，再写入新文件；现在先在同目录写完整、设只读并同步，再原子替换。复制失败、替换失败或提交前取消均保留旧文件。不改变信任提示，不自动信任陌生签名，不改安装方式偏好或图源入口。

## 手动回归

这批没有新的界面。仅在确实有扩展更新时执行；没有可用更新时不要求换仓库、卸载扩展或破坏文件来制造条件。

1. 进入「浏览 → 扩展」，下拉刷新，确认已装扩展仍在；有更新时，更新按钮和数量对应实际列表。
2. 选择一个原本能打开的图源扩展更新。安装完成后返回图源，打开列表或搜索，预期仍能正常使用。网页本身的网络故障需与扩展安装失败区分。
3. 若另有可更新扩展，开始下载后立即取消，再从原入口打开图源，预期旧扩展仍可用，下载不会自行重新开始。取消时若已经出现系统安装确认页，使用该页的取消按钮。
4. 重新更新刚取消的扩展，预期能完成，旧任务不会突然把它变成失败或取消。保持原安装方式即可，不要求启用 Shizuku。
5. 退出并重新进入应用，再打开这些图源。预期已装扩展仍可用，没有重复安装或长期卡住的下载状态。

取消后原扩展消失、同包名更新后跳到另一个仓库、重试被旧任务打断、返回后长期卡在下载或安装中，均算回归。阅读器滚动和缩放不属于这批改动，但此前缩放修复仍需单独验收。

## 自动验证与边界

自动测试覆盖签名匹配、多个仓库的最高版本选择、版本及包名不符、签名不符、多图源展示条目的真实包名、下载失败、中途取消、旧任务回调隔离、私有文件写入和替换失败，以及正常首次安装和连续更新。

共享调用方已核对：扩展列表与批量更新、后台更新通知、私有安装、旧系统安装页、PackageInstaller、Shizuku、扩展加载和信任判断。新增签名信息仅在内存模型使用，没有数据库迁移，不改备份格式、本地库索引、下载章节缓存或用户漫画数据。

本地格式检查、全量 debug 单测、数据库迁移校验和 Vienna Kotlin 编译通过。Windows 上会跳过 1 项仅适用于 POSIX 文件系统的只读文件替换测试；其他文件替换、失败与取消测试正常执行，POSIX 项由 Linux CI 执行。

编译和单元测试不能证明手机上的系统安装页、ROM 或 Shizuku 行为；这些保留为真机待验。用户操作，agent 负责日志与崩溃检查。这批目前只交付源码与 PR，手机上安装的是上一批缩放修复包。
