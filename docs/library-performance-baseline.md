# 第六批：书架查询基线与第一项优化

书架列表和“按篇目译名搜索”原来各自订阅一次全库查询。现在两者在同一个书架 ViewModel 内共享一份查询结果。首次显示、阅读进度写回、批量已读等引起数据库通知时，少执行一份作品、篇目、历史和分类的汇总查询。

本次没有新增界面。列表筛选、分类、计数、排序和搜索规则沿用现有实现；篇目译名仍独立监听，因此不需要退出应用才可搜到修改后的译名。数据库查询继续在后台执行，随书架 ViewModel 销毁而取消。共享结果只在内存中保留最新一份，不新增磁盘索引、身份来源或有效期。

## 测量

2026-11-17 用户确认实际库约为 500 部作品、3,000 个篇目。性能优化以这个规模及实际手机表现为准，更大规模仅按需作为边界检查。

使用仓库现有 SQL 建立内存 SQLite 数据库：500 部收藏作品、3,000 个篇目、750 条历史，含分类、书签及排除扫描组配置。每种状态交替执行两次查询与一次查询，各测 31 轮，报告中位数。两个路径在各状态下返回完全相同的行。

环境：Windows AMD64、Python 3.12.10、SQLite 3.49.1。

| 状态 | 原路径：两份查询 | 共享后：一份查询 | 少用的查询时间 |
| --- | ---: | ---: | ---: |
| 数据未变化 | 8.6 ms | 4.2 ms | 4.4 ms |
| 单篇目写回阅读进度后 | 7.8 ms | 3.8 ms | 4.0 ms |
| 1,201 个篇目批量设为已读后 | 8.2 ms | 4.0 ms | 4.2 ms |

第一次取得 SQL 结果为 4.3 ms。这里“第一次”指刚建好的内存数据库首次执行查询，不代表冷启动。以上仅为电脑 SQL 时间，不包含 Android 启动、磁盘读取、Kotlin 对象映射、筛选与绘制，不能解释为手机页面快了同样的毫秒数或百分比。真实连续写入可能被状态流合并，不能用写入条数直接乘本表时间估算总收益。这是小幅减少重复查询，现有证据不支持“明显提速”的结论，也不构成继续扩大架构改造的理由。

用户澄清规模前还测过 3,002 部作品、300,200 个篇目：同样三种状态少用 140–173 ms。此结果仅保留为边界参考，不用于判断当前使用是否需要优化。

复跑命令：

```powershell
python -B scripts/benchmark_library_subscription.py
```

测试还在真实 LibraryViewModel 上使用 500 部作品、每部 6 个篇目的汇总状态：改前确认两个数据库订阅，改后要求一个。该测试提供汇总模型，不创建 3,000 个真实篇目文件；真实 SQL 由上述基准另行覆盖。

## 影响面

- 修改仅限书架 ViewModel 的两个读取入口，不改 MangaRepository、GetLibraryManga 或 SQLDelight 的通用订阅行为；更新、历史、图源、详情页等共享调用方保持原路径。
- 书架后台原本已有持续收集任务，本次共享任务采用同一生命周期；保留原来的数据加载和返回页面方式，不引入空初值或额外等待。
- 作品身份仍为数据库 ID，进度、历史、书签、译名、分类等写入接口、备份恢复与文件移动接口均未改动。分类和排序结果继续使用同一份已解析的行快照。
- 自动测试覆盖进度和书签更新、译名编辑、添加与移除收藏、分类移动、标题改名、空库与恢复、下载数量变化、筛选切换、201 部作品状态变更、后台查询及生命周期结束释放订阅。它验证已到达数据库/仓库的变更能够传到书架，不替代 SAF 文件移动、目录改名和缓存恢复的真机验证。
- 2026-11-17 核对上游最新正式版 v0.21.3（2026-10-25 发布）：其书架只有一个全库订阅；Vienna 为篇目译名搜索增加了第二个。本次保留这项自定义功能，合并其重复的数据读取，不升级依赖或数据库结构。

## 手动回归

本地已通过 spotlessCheck、testDebugUnitTest、verifySqlDelightMigration 和 :app:compileViennaKotlin；书架新增的 4 项状态流测试全部通过，应用测试报告为 714 项通过、1 项跳过。另已通过 scripts/verify_library_queries.py 的统计、筛选与历史一致性检查。

安装本次改动的 Vienna 包后进行；只要未安装，手机上的表现仍属于旧包。需要操作文件或批量状态时，只使用可删除的测试副本。

1. 打开书架，记住当前分类、排序及列表位置，进入一部测试漫画详情，再返回书架。预期直接显示已有列表，分类、排序和位置保留，没有重新扫描或新增加载页。
2. 打开测试漫画阅读，连续下滑、反向翻回并跨一次篇目；拖动进度条、双击和双指缩放，再退出并重新进入。预期内容与页码对应、续读位置正确；返回书架后已读与未读计数更新。
3. 在测试作品详情给一个篇目设置独有译名，返回书架搜索该译名；再修改译名后返回重搜。预期新译名能命中，删除旧译名后旧词不再单独命中，搜索结果和显示数量一致。
4. 在已有筛选入口切换未读、已读或书签条件，再清除筛选。对少量测试作品改分类、批量标记已读后返回。预期实际列表、分类和计数同步；清除筛选后作品恢复，不需重启或刷新主库。
5. 从最近任务划掉应用，再手动打开，检查书架和刚才的测试作品。预期没有空库、重复记录或进度倒退。只对测试副本核对正常新增、删除或目录改名后刷新产生的变化，不对主库制造故障。

计数与列表不符、译名搜索不更新、作品移动后留在旧分类、返回白屏、列表意外跳位、续读丢失或异常已读均算回归。条漫手势、图片显示和预载路径没有改动；如果出现白块、跨章跳位或缩放无响应，也需要记录并检查。
