## 产品目标与必须保留的手感

Vienna 是用户个人修改的 Mihon 分支。用户不懂软件工程，希望 agent 判断哪些上游可靠性和性能改进值得吸收。当前界面与操作习惯就是产品基准，不因上游工程架构不同就整批覆盖自定义实现。

- 保留条漫连续下滑、惯性、反向翻回、横屏、双指与双击缩放、随机切换手势。
- 保留图片提前定高、首帧对齐、跨作品防跳位、相邻篇目预载及拖进度条后的接续。
- 保留跳过已读、完成判定、进度锁和阅读会话规则；不改历史展示和续读落点。
- 本地库先显示最后一次确认正常的缓存。普通进入、返回和筛选不能等待文件扫描、压缩包读取或封面生成。
- 稳定数据库 ID、进度、历史、已读、书签、译名、标记、自定义排序及封面必须保留。来源名和文件名权威，中文译名只是显示壳。
- 沿用已有菜单与入口；不增加自动提示、阻塞加载页、无必要确认或顶级按钮。

本轮暂不做条漫图片分块、整库迁移、阅读器重写、WebGPU、全面依赖注入迁移及无关工具链升级。网络整章预加载、ComicInfo 日期和识别排在本地可靠性之后。这些大改需要另有方案与验收依据，不能夹进性能优化。

### 下载逻辑中不能随手简化的部分

相关文件在 `app/src/main/java/eu/kanade/tachiyomi/data/download/`：

- `Downloader.kt`、`DownloadRun.kt`：新任务必须等旧网络与文件工作退出。中间任务即使在调度前取消，第三次启动也不能越过最早的写入者；现有原子启动和发布门控承担这个约束。不要改回取消后立即置空，或会绕过旧任务的懒启动。
- `DownloadCache.kt`：恢复、扫描和修改按顺序提交，查询读取最后完整快照。改锁与共享流前查遍调用方。
- `DownloadIndexFile.kt`、`DownloadDirectoryListing.kt`：原子缓存替换、暂时空目录保护。SAF 返回空不一定代表真实删除，也不能设固定数量门槛永久遮蔽真实变化。

第五批没有改本地源作品索引、数据库结构或备份格式。下载缓存和本地源索引不是同一个系统，不要混淆。

## 第六批的具体执行顺序

### 1. 先记录可复现基线

优先复用现有性能测试与测量工具。可调查书架状态整理、详情列表处理、本地索引读取、下载缓存通知到页面计算的链路；这些只是调查入口，尚未证明是瓶颈。

在 `docs/` 记录源码提交、手机、系统、包变体、存储提供器、作品/篇目规模、筛选条件、冷或热缓存、操作步骤、次数、原始数值和限制。前后同设备、同素材、同条件，不能拿 debug 和 Vienna 作性能对照。

| 场景 | 操作与记录 |
| --- | --- |
| 冷启动 | 进程结束后启动；区分已有磁盘缓存恢复与首次扫描。记录到可用书架的耗时、磁盘访问与主线程工作，不清数据或索引制造冷启动 |
| 详情和书架返回 | 详情进入阅读器停留超过五秒，返回详情及书架。记录首次可见、最新状态更新时间、重复查询/整理次数、位置是否保留 |
| 大库筛选 | 3,000 部以上作品、大量篇目；切换全部/在读/剩余/读完、标记和搜索。核对计数与列表，记录耗时和整理次数 |
| 批量操作 | 仅测试数据上的标记、书签、排序及涉及的移动/改名，记录保存与通知次数、更新时间，核对稳定 ID 和用户字段 |

设备真实库不足时，自动测试补足规模与正确性，设备结果注明实际规模。不得静默向主库灌入几千部作品，不得把模拟速度当作手机结果。每个可重复场景争取至少五次，列出中位数与最慢值；不足时说明，不能用一次波动宣称收益。

## 验证与交付约束

代码修改完成后先执行：

```powershell
.\gradlew.bat spotlessCheck testDebugUnitTest verifySqlDelightMigration
.\gradlew.bat :app:compileViennaKotlin
```

失败先本地复现修复，无法运行则说明阻碍，不跳过。debug 单测编译是正常验证，不代表可安装 debug。跨模块改动前后查共享调用方，定向测试不能替代影响面检查。

仅在用户要求构建/安装时准备同签名、单 arm64 Vienna：

```powershell
.\gradlew.bat --init-script .gradle\no-abi-split.gradle :app:assembleVienna
.\gradlew.bat --init-script .gradle\no-abi-split.gradle :app:installVienna
```

先构建核对元数据、签名、设备，再安装。init script 在忽略目录中，通过 `androidComponents.finalizeDsl` 设置 `reset()`、仅 `include('arm64-v8a')`、关闭 universal；缺失按 AGENTS 重建，不改 `app/build.gradle.kts` 的变体和 splits。

当前产物 `app/build/outputs/apk/vienna/MihonVienna-2.4.0-arm64-v8a.apk`。目录残留旧包，必须核对 `output-metadata.json` 的 versionCode/versionName、ABI 和实际文件，不凭 UP-TO-DATE 判断。未经要求不升版本、不发 Release、不推 tag。

签名身份在 `D:\DATA\keys\mihon-release.keystore`，密码在忽略的 `keystore.properties`。**不要清理或删除 D:\DATA\keys，不输出或提交密钥密码。** 历史误删导致过数据损失；不能以卸载重装、清数据绕过签名问题。

一个自洽单元对应一个分支、一个 PR；推送前 fetch，落后 rebase，保留他人改动。PR 开 squash auto-merge，推送后立即报告本地检查与待验项，无依赖不必等 CI 才回话。默认交付源码，不自动安装，正式发布另按 [发布流程](release-process.md)。

临时文件放已有 `_tmp/`，仅清理归属本任务的文件，不删他人日志、脚本或工作树。手机同样只清本次生成的临时文件；不清数据、不撤存储权限、不删索引、不重建主库。
