# 下载重启与索引回归

## 改了什么

以前暂停后立即继续，旧下载任务可能仍在关闭网络或文件，新任务已经开始写同一篇目。现在保留旧任务的结束状态，新任务等它完全退出后才开始。连续多次暂停、继续也遵守这个顺序；旧任务的完成或错误不能停止新一轮下载。调整队列时同样先等退出，再接手文件。

以前下载索引的启动恢复、目录扫描和缓存写入各自执行，旧结果可能覆盖后来的新增、删除或改名。现在先完成启动恢复，扫描和修改按同一把锁提交，查询读取最后一次完整快照。缓存先写临时文件并同步，再原子替换旧文件；写入失败或取消时保留原文件，并清理临时文件。冷启动排队的扫描在缓存恢复后重新检查时效，已有有效缓存时不重复扫描。

目录无法列出，或列出为空但旧索引中的文件仍存在时，保留最后一次完整索引。确认文件已不存在后允许清空，不按固定数量拦截删除。扫描失败后沿用原有一小时自动核对间隔，用户主动刷新下载索引和已确认的目录变化仍可立即重新核对。图源尚未初始化时不提交空索引。

本批没有新增界面。正常情况下只能感觉到下载暂停、继续和重启后的下载标记更稳定。条漫图片加载、预载距离、双击缩放、双指缩放、惯性和阅读完成规则不作调整。本地源作品索引、数据库结构与备份格式也不在本批修改范围。

## 手动回归：五步

只选择一部可以重新下载的网络图源测试作品，使用两三个篇目。不要用唯一副本，不对主库做故障测试。之前复制到本地源的 Vienna-Test 漫画可用于阅读器检查，但本地文件不会经过网络下载队列，不能代替本次下载测试。

1. 从测试作品详情长按选择两三个篇目，使用原有下载入口加入队列；进入「更多 → 下载队列」。确认只有选中的篇目开始下载。
2. 有进度时点暂停，紧接着点继续，再重复一次；下载中把应用切到后台后返回。预期队列继续推进，完成后退出队列，不出现重复任务或反复从零开始。网络自身限流、断线不作为本次修复已经失败的依据，agent 结合日志确认原因。
3. 等下载完成，返回作品详情，确认下载标记与实际篇目对应；从最近任务划掉应用后重新打开。预期下载标记和数量仍正确，普通进入作品详情不要求重新扫描下载目录。
4. 打开已下载篇目，连续下滑、反向翻回、跨到下一篇、拖动进度条，测试双击与双指缩放；退出后重新进入。预期图片完整、页码和续读落点正确，没有新增白块、跳位或缩放失效。
5. 在测试作品详情用现有菜单删除其中一个篇目的下载文件。预期只清掉该篇目的下载标记和计数，其余篇目仍能打开；重新下载刚删的篇目，完成后标记恢复。此处只删可重新下载的测试内容。

重复任务、完成后长期停在队列、重启后下载标记丢失、已删篇目仍显示下载完成、数量与篇目不对应，以及阅读时新增白块、跳位、错误已读或续读倒退，均算回归。

## 自动验证与边界

- 本批新增 24 个测试。下载任务测试覆盖旧写入退出后才能重启、连续三次切换不越过最早任务、中间任务尚未调度就被取消、取消等待中的重启后不再执行，以及旧任务身份不再有效。
- 真实临时文件测试覆盖完整缓存替换、替换失败、提交前取消、首次写入失败、重新打开后的字节一致与临时文件清理。中断遗留的暂存文件不参与读取，下次写入复用同一路径，避免每次中断多留一份文件。
- 目录和缓存测试覆盖目录无法访问、各级临时空结果、真实删空、新增、篇目改名、批量删除、作品目录改名、来源移除、切换根目录、图源初始化超时、扫描中再次失效，以及冷启动恢复后立即修改和再次恢复。
- 大库用例使用 3,002 部作品、12,008 个篇目条目，执行 100 部作品的目录改名和删除，再验证计数与缓存恢复。普通查询与恢复不增加目录扫描次数。这是模拟文档提供器的规模与正确性测试，不能据此声称手机滚动更快。
- 影响面检查包括下载管理器的开始、停止、暂停、重排和删除，下载完成及改名补偿的缓存更新，以及存储目录变化、备份恢复和高级设置的索引失效入口。书架、更新、作品详情和“仅已下载”筛选继续读取同一索引和变更通知，恢复后通知页面更新。共享调用方的入口签名保留。

暂停续传的真机状态、网络图源差异、SAF 提供器实际行为和阅读手感仍待安装后确认。由用户操作手机，agent 检查日志与崩溃；不要求清数据、撤销权限、删索引或制造文件损坏。

## 上游核对

本批以 2026-11-17 核对的上游正式版 v0.21.3 为参考，吸收下载重启前等待旧任务结束、扫描前等待索引恢复和锁内编码缓存的设计，适配 Vienna 现有调用方与篇目改名补偿。没有带入整套依赖注入或读写接口迁移。
