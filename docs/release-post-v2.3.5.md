# Mihon Vienna 2.3.5

这一版把音声的队列、最近播放和账号页重新理了一遍，另外修了历史页的篇目标题和本库的导入日期，并给应用更新加了一个启动时的提示弹窗。

**覆盖安装即可，不用卸载。** 有两处会碰到已有数据，先说明：

- 播放队列第一次打开时会按「作品 → 文件夹」重新排一次。音轨一首不少，顺序变成同一作品、同一文件夹的音轨连在一起——这也正是播放顺序
- 本库里有作品新加入篇目文件时，会按加入时间重新记一次导入日期，于是它会排到「导入日期」最前面。以前只有从导入界面加进来的作品才会这样

> 这一版是 2.3.5 的重新打包（`versionCode` 221）。已经装过上一份 2.3.5（220）的，同样可以直接覆盖，不用卸载。

## 应用更新：启动时的提示弹窗

以前只有「更多」标签上的一个小红点，和一个要自己去「关于」里点的检查更新。现在后台检查到新版本时，打开应用会直接弹一个提示，写明是哪个版本，并给三个选择：

- **忽略更新** —— 这个版本以后不再问。下次发了新版本，仍然会弹
- **知道了** —— 这次先关掉，下次打开应用还会弹
- **更新日志** —— 直接打开这次的发布说明，就是「关于 → 检查更新」打开的那个页面，里面有下载按钮

小红点保留。它和弹窗是同一件事的两半：不想被打断的人把弹窗关掉就行，红点还在那里；反过来，弹窗也不会因为看过一次就再也不出现，除非点了「忽略更新」。

首次使用的引导界面在屏幕上时不会弹，两个全屏的东西不抢同一时刻。

## 音声：播放列表改叫播放队列

名字换掉是因为这块地方实际在回答「接下来放什么」，不是一份收藏。

- **一部作品只出现一次**，作品里的文件夹作为下一级行。只有一个文件夹的作品不显示文件夹行——那个路径已经写在作品名下面
- **展开和收起会记住**。没人动过的行跟着正在播放的音轨自动展开；你自己收起过的行，即使正在播放也保持收起
- **左滑露出删除按钮**：作品、文件夹、音轨三层都是同一个手势。滑一下只负责露出按钮，删不删由你点
- 播放页顶栏多了一个队列按钮。队列页已经在返回栈里时直接回到那一页，不会每按一次就压一层新的

## 音声：播放历史改叫最近播放

以前一行作品可以展开成一条条音轨，每条带进度条、日期和「加入队列」按钮。想看一眼「最近听过哪几部」的人，看到的是一个日志。

现在**一行就是一部作品**：作品名、上次停在哪首，右边一个播放键，接着那首停下的位置放；那首已经放完就从头放。展开、进度条、逐条音轨都去掉了。

队列和最近播放现在是同一个页面的两个标签，中间不用退回上一级。

## 音声：账号页

菜单里的「退出登录」换成了「账号」，进去是四行：

- **用户名**
- **邮箱**：未绑定显示「未绑定」，可以点「在浏览器中绑定」。绑定要在自己的邮箱里发一封信再等网页那边轮询，这半件事交给浏览器更顺手。已绑定的可以解绑，会先问一次，并说明解绑之后忘了密码就没法找回
- **修改密码**：新密码 + 确认，至少 5 个字符（和注册同一条规则），可以点眼睛看明文，成功后弹「密码已修改」。服务端不要求旧密码，所以这里没有那个输入框
- **退出登录**

游客账号不能改密码也不能绑邮箱，页面上会写明原因。

## 音声：只看带字幕的作品

菜单里多了「字幕：只看 / 字幕：不限」。它是个筛选，不是一个排序：切换后当前列表原地重新加载，标签页不会跳走。状态会记住，两个状态各自缓存，来回切不用重新请求。

收藏页不给这个开关——那份列表在本地，没有请求可以收窄。

实测：62897 部作品里有 8032 部带字幕；搜「病み」从 47 部收到 2 部；标签页从 3534 部收到 443 部；推荐流一页 100 部里 41 部。

## 音声：排序菜单

顺序改成 **随机 → 销量 → 评分 → 收藏时间 → 发售日 → 加入日期**。

「下载量」改叫「销量」：这个数就是 DLsite 自己的销量，不是本 App 的下载次数。发售日和加入日期留在最后，它们回答的是「作品什么时候出现」，而收藏时间回答的是「什么时候进的书架」。

## 音声：作品页

- **其他语言版本**：社团名下面一排语言小标签（日语 / 中文 / 英语），当前版本实心、点不动，点别的直接换过去。换版本是 replace 而不是 push，返回键回上一页，不会一层层退。只有真的存在多个版本的作品才有这一行
- **相似作品默认收起**，标题右边写着有多少部，展开过一次就保持展开。以前一屏高的卡片会把曲目列表整个顶下去
- **社团名和声优并到一行**，用「·」隔开
- **标签从最多 12 个、换行铺开，改成一行横向滚动**

相似作品以前在翻译版上整块是空的：推荐服务只对原版有向量，中文版查不到，日文版一查就是一整页。现在直查为空时会拿数据库里登记的姊妹版本再问一次，只问这一层。

## 阅读器：两个悬浮块的位置会记住

音频条和上下章跳转盘以前只活在当前界面里：退出漫画、重启 App 就回到最左边。

现在两个位置都存成「可移动距离的比例」，所以：

- 退出漫画再进来，还在原处
- 重启 App，还在原处
- 转屏之后按比例落回去，不会一边贴在边上
- 音频条的紧凑形态和顶栏形态共用同一个位置

## 历史：本地篇目的标题跟着库级设置走

历史条目的标题以前直接读每部作品自己的 `chapter_flags`，那是「上次打开详情页时」写下的快照。把本地篇目切成「只显示译名」之后，只有打开过详情页的作品会跟着变，其余条目还停在旧值，历史页就新旧混着显示。

现在历史跟详情页、阅读器、标记列表一样，套用库级的显示模式。只作用于展示用的副本，不写回数据库——翻一遍历史不会改掉你的设置。

## 本库：从外部拷进来的篇目会被发现

以前在文件管理器或同步脚本里往已有作品的文件夹放一个篇目文件，App 不会知道，除非你手动点刷新。作品的导入日期也就停在它第一次出现的那天。

现在**进本库页面、以及 App 回到前台时**，会在后台做一次同样的扫描：

- 不加提示、不占界面，书架仍然是缓存里的那份
- 只读 mtime 变过的文件夹，没变过的直接沿用上次记录（列出文件夹里的文件是这趟扫描里最贵的一步）
- 五分钟最多一次，来回进书架不会反复扫
- 新篇目加进来后，作品按加入时间重新记一次导入日期，于是会排到「导入日期」最前

## 两个标签图标会动

「最近更新」的铃铛在你切到它时摇一下，「本地库」的文件夹会先压扁再弹回来。原来都是静态图标。动作都很短（420 ms 和 300 ms），读起来是图标落定，不是特效。
