# Mihon Vienna 2.3.8

> 队列一次只展开一个作品；跳过已读只管往后接续；退出阅读器回到原来那个导航页；本地库的 webp 导入与封面不再漏。

**覆盖安装即可，不用卸载。** 这一版没有动用户数据，也没有改签名。

---

## 队列：一次只展开一个作品

以前展开作品 A 后再展开作品 B，两个会同时开着。现在展开 B 时 A 自动收起，任何时刻只有一个作品展开；再点 B 一次可以全部收起。文件夹行在同一作品内也是这个规则，换到另一个作品时它的文件夹状态不受影响。

这个手风琴 10 月 19 日在 `feature/audio-video-playback` 分支上做过，但那条分支一直没合回 main，main 上仍是 2.3.5 重做时的多展开模型。这次在当前的作品分组、文件夹分组和持久化模型上重做，没有直接搬旧代码。

两处容易漏的边界也补了：展开一个作品时，其余作品会被**显式**写成收起，否则没被碰过的行会回退去跟随当前曲目、自己又弹开；手风琴启用后新加入队列的作品，也不会因为「成为当前曲目」而多展开一个。旧版本残留的「多个同时展开」状态，在下次点开任意一行时收敛成一个。

## 跳过已读：只管往后接续

以前开了「跳过已读篇目」，阅读器**一打开就把已读篇目整段从章节链条里删掉**。链条在打开那一刻按当时的状态裁剪，之后整个会话不变。于是「下一篇」是裁剪后列表的相邻项，在原始合集里可能隔着好几篇；随机漫画用的是几秒前预加载的章节快照，与实时进度错开时更明显。半读完的篇目也可能整段从链条里消失。

现在章节链条保持完整，只有**往后接续**时跳到第一篇未读：

| 场景 | 落点 |
| --- | --- |
| 从进入时未读的篇目往后读 | 往后第一篇未读 |
| 从已读篇目重读 | 紧邻的下一篇，逐篇走 |
| 中间夹着半读完的篇目 | 不跳过，按顺序出现 |
| 往回翻 | 紧邻的上一篇，已读也能翻回去 |
| 后面全是已读 | 紧邻的下一篇，不会卡在篇末 |

往回方向永远不跳过。上一章保持紧邻、不重新计算，这是刻意避开的：早先一版每次切章都重算前后两章，跳过落点的「上一篇」会变成一个从未加载的远章，跨章瞬间要在视口旁边删旧页、插转场卡、再整话预载，三次结构变异叠在一起，就是当时反复闪现和强行拼接手感的来源。

跳过的已读篇数会传给两个阅读器适配器和转场界面，从章号差里减掉，远程源不会把跳过的已读篇目误报成「缺 N 话」。设置页的副标题也改成了现在这个语义：往后接续时跳到下一篇未读，往回翻不受影响。

## 退出阅读器：回到原来那个导航页

以前从「本库」进阅读器、退出来，有时会落到「书架」。返回动作本身不改 tab，能否保持全看系统有没有保住 Activity 的保存状态；进程被回收后冷启动、或返回时实例已被销毁，都没有这份状态，主页就用写死的书架重建。

现在把上次所在的 tab 记到偏好里。系统状态还在时以它为准，没有时用偏好兜底，两种情况都回到进入阅读器前的那个页面。从桌面快捷方式或通知指定 tab 时，仍以指定为准。首次启动、没切过 tab 时默认还是书架。

## 本地库：webp 的导入与封面

webp 在阅读器、格式表和解码库里本来就能读。这一版修的是两处与它相关的缺口：

- 本地导入的扩展名白名单原来手抄了 7 个扩展名，是格式表之外的第二份名单。现在和页数统计、阅读器共用同一张表，只保留 `ComicInfo.xml` 一个非图片特例。
- 章节封面优先名原来写死 `cover.jpg`。现在按 `cover` 主干加任意支持的图片扩展名判断，`cover.webp` 会和 `cover.jpg` 一样排在最前，而不是掉回页码顺序里。
