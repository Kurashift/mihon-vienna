# 已下载篇目多选底栏崩溃回归

## 问题与改动

2026-11-17 的真机报告显示，选中已下载的网络篇目、底栏显示删除按钮时，发生 index: 5, size: 5 越界。底栏的书签、标记、阅读、下载、译名和删除共有六类标签，旧代码只创建五个状态，读取删除标签时就会崩溃，不需要真的点击删除。

这组状态和编号自 2026-09-04 的 c32ae87f242 提交起便已不匹配，下载回归测试暴露了这条既有路径。作品详情的列表和网格共用此底栏，「更新」页多选已下载篇目也会走到它。

现在用按钮身份记录当前展开的唯一标签，删除按固定下标读写列表的逻辑。长按仍只展开文字，一秒后恢复；连续长按不同按钮会取消前一次计时。按钮布局、颜色、下拉菜单、实际删除入口和文件操作不变。修复不修改数据库、下载任务、索引和阅读器。

## 手动回归：五步

1. 打开一部有已下载篇目的网络图源漫画，长按选中一个已下载篇目。预期底栏正常出现，包括删除按钮，应用不退出；不需要点击删除。
2. 再选一个未下载篇目，观察混合选择时的底栏，然后取消其中一个选择。预期下载、删除与阅读状态入口按当前选择显示，不因按钮增减崩溃。若作品支持列表和网格，可在两种布局各重复一次。
3. 长按删除按钮，松手后等约一秒。预期只显示按钮文字，然后恢复，不删除文件；再快速长按另一个底栏按钮，预期只展开最后一个按钮的文字，前一个计时不会提前收起新标签。
4. 返回「更新」页，长按选择一个已下载条目，再退出选择。预期底栏可以正常显示和关闭，不崩溃。如果当前没有已下载的更新条目，本步记录为待验，不需要为测试刷新整个主库。
5. 打开本地测试漫画，长按选择一个或多个篇目，再取消选择。预期现有书签、标记、阅读状态、译名与红色本地文件删除入口按原规则显示；只观察入口，不执行删除。返回书架后长按选中作品、取消选择，确认相邻的书架多选底栏仍正常。

打开底栏就退出、标签串到其他按钮、长按直接执行删除、底栏入口消失或位置变化，都算回归。整个过程无需删除主库文件或修改已读状态。
