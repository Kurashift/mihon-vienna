# 本地本子导入与篇目移动计划

> 状态：第一阶段主流程已落地，进入设备验收与低风险收尾
> 最后更新：2026-08-23
> 说明：本文档记录本次功能的产品约定、技术边界和后续讨论结果。实现前继续更新；未确认内容不会直接视为实现承诺。

## 目标

在本库右上角三点菜单中增加“导入本地本子”，让用户可以选择一个或多个本地本子目录，并将它们安全地导入 Mihon 的本地源目录。导入时可以选择保留文件夹或转换为 CBZ，可以复制并保留源文件，也可以在导入成功后删除源文件。

在本地漫画详情页中，复用现有章节多选操作增加“移动到…”，把选中的篇目移动到其他本地漫画/作者条目，同时保留阅读进度、已读、书签、历史、译名、标记、备注和自定义封面等资料。

在本地漫画详情页右上角三点菜单中另外增加“导入本地本子”。该入口的目标条目固定为当前详情页，不再要求用户重复选择目标漫画/作者；格式、复制/删除源文件、冲突和后台进度规则与本库总入口完全一致。该按钮只对本地源详情页显示，不改变网络漫画的下载语义。

## 已确定的产品约定

### 1. 本地库结构

- Mihon 顶层本地目录继续作为本库列表中的漫画条目。
- 用户可以把这个条目当作漫画、作者或作品分组使用，但第一阶段不新建独立的“作者”数据模型。
- 导入的图片文件夹或 CBZ 文件作为该条目下的一个篇目。
- 原始文件夹名、文件名和来源名仍是权威数据；不自动翻译或重写用户命名。

### 2. 导入格式

正式导入开始前，只为**图片文件夹来源**提供最终格式选择：

- **保留为文件夹**（默认）：保留图片文件和原始文件名，导入速度最快，便于用户继续管理。
- **打包为 CBZ**：只打包原始图片，不重新编码或压缩图片，避免画质损失。

已经是 Mihon 支持的篇目文件时不显示多余的格式转换选项，始终保持原格式并直接复制/移动。当前本地源明确支持 `ZIP`、`CBZ`、`RAR`、`CBR`、`7Z`、`CB7`、`TAR`、`CBT`，并单独支持 `EPUB`。

格式选择只决定图片文件夹在 Mihon 目录中的目标形式，不修改来源。文件夹到文件夹直接复制/移动目录；已有归档和 EPUB 直接复制/移动文件，不重新打包、解包、编码或生成内部文件名。

选择“保留为文件夹”时，篇目目录中的所有直接文件都原样保留，包括图片、`cover.jpg`、`ComicInfo.xml` 以及其他用户附件；阅读器只读取其中支持的内容。选择“打包为 CBZ”时，才只收入 Mihon 能识别的图片、明确封面和元数据；检测到无法放入 CBZ 的附件时，不自动删除来源目录。

项目现有下载流程已经使用 `ZipWriter` 生成 CBZ，并采用不重复压缩图片的 ZIP Store 模式。导入功能直接复用这套能力，不要求用户安装额外压缩程序；新增工作主要是来源目录读取、稳定排序、写入进度、校验和失败清理。

### 3. 导入方式

界面不直接使用容易产生误解的“复制/移动”二选一，而显示：

- **复制，保留原文件**（默认）
- **导入成功后删除源文件**（需要用户主动勾选）

第二种方式技术上通常是“复制到临时位置 → 校验 → 正式落盘 → 数据库同步 → 删除源文件”。只有在同一存储且提供器支持安全重命名时，才可能接近真正的文件移动速度；跨存储或 SAF 提供器时不能假设它比复制更快。

默认保留源文件，避免误删用户原有收藏形式。删除源文件只发生在目标文件完整、数据库同步成功之后；如果清理失败，保留源文件并把结果视为“已导入，但原文件未删除”。

批量选择“导入成功后删除源文件”时，采用**逐本提交**，不等待整个批次复制完成：

1. 处理一个本子并写入目标临时位置。
2. 校验当前本子的文件数、总字节数和可读取性。
3. 将目标提升为正式篇目并完成数据库/索引同步。
4. 只删除这个已经完整成功的源本子。
5. 释放临时资源后再处理下一本。

因此批量导入 40GB 内容时，额外存储占用通常接近“当前正在处理的最大单本”，而不是整批 40GB。已经成功提交并删除来源的本子要写入任务记录，应用重启后从下一本继续，不能重复导入或重复删除。

不能在单个本子内部采用“复制一张图片就立即删除源图片”的方式：如果中途取消、空间不足、目标损坏或数据库同步失败，会把一本书拆成两半，来源和目标都不再完整。单本仍以整个目录或整个归档文件作为最小安全提交单位。

只有在来源和目标位于同一、可确认支持原子重命名的文件系统时，才允许优先直接移动；不能仅因 API 提供了 `rename` 就假设它安全。跨存储或 SAF 无法确认原子性时，统一使用逐本复制、校验、删除。开始每一本前检查可用空间；无法可靠查询剩余空间时继续复制但禁止提前删除来源。

### 4. 目标条目

- 一次批量选择的多个本子，默认导入到同一个目标条目。
- 目标可以是已有本地条目，也可以现场创建新条目。
- 新条目的标题默认来自用户输入；目录名经过非法字符和同名冲突校验。
- 不额外创建第二份作者事实来源，不强制生成 `ComicInfo.xml`。

#### 按一级目录自动创建合集

- 本库总入口继续复用现有“从文件夹导入本子”，不增加新的顶级按钮或独立导入模式开关。
- 当所选根目录明确呈现 `根目录/作者目录/本子目录或归档` 两级结构时，应用自动把一级作者目录映射为同名合集，把其下有效本子映射为篇目。
- 普通的“父目录直接包含多个本子”保持原有行为，仍由用户选择一个目标合集；日常本地源扫描不因此递归化。
- 自动分组只从本库总入口启用。从漫画详情页进入时，目标仍固定为当前合集，即使来源是两级目录，也只是把其中本子导入当前合集。
- 预览在现有来源和归属区域内显示识别出的合集数、本子数、将复用和新建的合集数，以及被忽略的根目录散落项目，不增加额外确认按钮。
- 同名已有合集优先复用原本地源 URL 和数据库 ID；同一作者来自多个选择根目录时合并到同一目标合集。
- 不同原名经过非法字符清理或 Unicode 规范化后发生目标重名时阻止开始，提示用户先整理源目录；已有本地合集身份存在歧义时同样不猜测归属。
- 根目录中的 `.nomedia`、散落图片、元数据或其他非作者目录项目不参与建合集，也不会在“成功后删除源文件”时被删除。

### 5. 封面

- 如果来源文件夹中存在明确的封面文件（例如 `cover.jpg`），优先使用它作为封面候选。
- 封面文件仍然属于篇目原始内容的一部分，不能因为被识别为封面而从导入内容中排除。
- Mihon 从该图片生成或复制一份独立的封面缓存/封面文件；原始篇目内容保持完整，不要求缓存与原图字节完全相同。
- 没有明确封面文件时，使用第一张有效图片作为候选。
- 封面缩略图生成和缓存尽量在导入后后台完成，不阻塞导入流程。

### 6. 同名冲突

- 导入前汇总显示冲突篇目并弹出提示框。
- 默认策略是**跳过**，不覆盖目标文件，也不默认生成第二个相同的 Mihon 篇目。
- 被跳过的源文件不能因为选择了“导入成功后删除源文件”而被删除。
- 文件夹、`ZIP`、`CBZ`、`RAR`、`CBR`、`7Z`、`CB7`、`TAR`、`CBT` 和 `EPUB` 去除扩展名后使用同一套规范化篇目名参与冲突检查；例如 `A/`、`A.cbz` 和 `A.rar` 默认视为同名冲突。
- 名称相同先标记为冲突；预览阶段只使用图片数、字节数、文件名签名等轻量信息，不能把“尚未完整校验”误报为内容相同。
- 实际写入时再完成可读取性和逐文件字节校验；即使轻量签名相同，也不自动覆盖或合并。
- 后续可讨论“保留为新名称”，但不作为默认行为。

### 7. 文件夹输入范围

第一阶段支持：

- **一个本子的识别标准是：带本子名称的文件夹，其内部同一层级直接存在一组图片。** 不递归把子目录中的图片混入当前本子。
- 所选目录直接包含图片、且没有有效的本子子目录时，所选目录本身视为一个本子，并使用该文件夹名作为篇目名。
- 所选目录存在一个或多个直接包含图片的子目录时，所选目录视为批量导入容器，每个有效子目录分别作为一个候选本子，并在应用内支持多选。
- 批量导入容器根部的普通散落文件统一视为无关容器文件并忽略，包括随机图片、未知 XML、`.nomedia` 等；它们不会形成“根目录中的图片”篇目。精确命名且可解析的漫画级封面和 `ComicInfo.xml` 按“已符合 Mihon 结构的输入”规则单独处理。
- 预览页只显示“已忽略根目录散落文件 N 个”的摘要，可展开查看名称，避免静默遗漏。
- 选择“导入成功后删除源文件”时，只删除完整导入并校验成功的已选本子子目录，绝不删除批量导入容器及其散落文件。
- 常见图片格式和已知元数据文件可以识别。
- 除图片目录外，允许通过系统文件选择器单选或多选 Mihon 本地源已经支持的篇目文件；兼容文件固定保持原格式直接导入。
- 不对未知的多层目录结构进行递归猜测；结构不明确时提示用户调整目录。
- 候选列表按需加载并支持大批量分页/虚拟化，不设置会静默漏项的固定数量上限。

Android 标准目录选择器本身通常不能一次多选多个目录，因此文件夹采用“选择父目录 → 应用内多选直接子目录”；CBZ 等独立文件采用支持多选的系统文件选择器。导入入口中提供“选择文件夹”和“选择篇目文件”两个清晰选项。

### 8. 已符合 Mihon 结构的输入

- 如果选择的是外部的单个图片文件夹，它可以直接作为一个篇目导入目标漫画/作者条目。
- 如果选择的是外部的 `ZIP`、`CBZ`、`RAR`、`CBR`、`7Z`、`CB7`、`TAR`、`CBT` 或 `EPUB`，原样复制/移动到目标条目，不提供转文件夹或转 CBZ 的附加步骤。
- 图片文件夹才可以在“保留文件夹”和“打包为 CBZ”之间选择；归档文件的格式整理不属于本次导入功能。
- 如果选择的是一个已经按 Mihon 方式组织的外部漫画目录，其直接子目录和支持的篇目文件共同列为批量候选，导入到已有或新建目标条目。
- 完整 Mihon 漫画目录根部的已知漫画级资料需要单独识别：导入到新建条目时保留有效的漫画封面和 `ComicInfo.xml`；导入到已有条目时默认不覆盖目标已有封面或元数据，并在预览中说明这些文件将被忽略。
- 上述漫画级封面只适用于“目录根部是漫画容器、直接子项是篇目”的结构；篇目文件夹内部的 `cover.jpg` 仍属于该篇目的原始内容，同时可以作为篇目封面候选。
- 如果来源已经处于当前配置的 Mihon 本地源根目录内，先按规范化绝对路径/URI 判断是否已被本库收录；已收录项显示“已在本库”并跳过，不能复制出第二份。
- 如果来源位于 Mihon 根目录内但尚未进入可靠索引，只对对应漫画目录做精确同步，不经过“复制到自己”的导入流程。
- 不能只凭文件名判断“已在本库”；路径/URI、目标条目和实际文件身份都要参与判断，避免不同目录中的同名本子被错误跳过。
- 原始篇目名称必须尽量原样保留；目标提供器拒绝某个名称时，单独提示该项需要改名，不能静默清理或重写用户文件名。

### 9. 图片名称与顺序

- 不修改篇目内部的图片名称，不自动补零，也不重排文件名。
- 文件夹模式保留原文件名，由 Mihon 阅读器继续采用现有的自然文件名排序。
- CBZ 模式在写入条目前先采用同一套自然文件名排序，再按该顺序写入压缩包；不能依赖 Android 文件系统不稳定的目录返回顺序。
- 例如 `1.jpg`、`2.jpg`、`10.jpg` 保持文件名不变，阅读顺序仍为 1、2、10。

### 10. 导入进度与后台任务

- 导入确认后显示页面内进度条，至少包含总进度、当前本子名称、已完成/总本子数以及已复制/总字节数。
- 总进度优先按字节计算，避免一个超大本子在按文件数统计时长时间看似卡住。
- 批量任务按本子逐个执行并逐本提交；每本成功后立即按用户选项清理该本来源，进度同时显示当前本子和整个批次。
- 用户离开页面或应用进入后台后，导入继续执行，并在系统通知栏显示相同的确定进度条。
- 通知栏显示当前本子和整体完成数，并提供“取消”操作；取消只停止尚未完成的工作，不删除源文件。
- 导入结束后通知汇总成功、跳过和失败数量；前台页面可读取同一任务状态，不维护第二份进度状态。
- 使用可持久化的后台任务记录保存来源 URI、目标和选项，避免应用进程被系统回收后把半成品误判为完成。

## 建议的用户流程

### 导入本地本子

1. 打开本库右上角三点菜单，点击“导入本地本子”。
2. 选择一个本子目录，或选择包含多个本子目录的父目录。
3. 应用按“带名称且直接包含图片的文件夹”生成候选列表；存在有效子目录时忽略容器根部散落文件，并支持对子目录候选多选。
4. 预览名称、图片数量和封面候选。
5. 如果来源包含图片文件夹，选择“保留为文件夹”或“打包为 CBZ”；已有 Mihon 兼容篇目文件固定保持原格式。
6. 选择“复制，保留原文件”或“导入成功后删除源文件”。
7. 选择已有本地条目，或创建新条目。
8. 查看重名冲突汇总，默认跳过冲突项。
9. 确认后执行导入，页面内显示当前本子、整体字节进度以及已完成/跳过/失败数量。
10. 离开页面后通过通知栏继续显示进度并支持取消。
11. 导入完成后只对受影响条目做精确增量刷新。

从漫画详情页进入时，步骤 7 的目标选择被当前条目替代；页面在确认前明确显示“导入到：当前漫画/作者名称”。

### 从详情页移动篇目

1. 在本地漫画详情页进入现有章节多选模式。
2. 长按一篇或继续勾选多篇，在现有底部操作栏点击“移动到…”。该操作只对本地源显示。
3. 打开目标选择页，默认列出已有本地漫画/作者条目，支持搜索；当前条目不作为有效目标。
4. 用户可以选择其他已有条目，也可以现场创建新条目。
5. 确认页显示选中篇目数、来源条目、目标条目和同名冲突；冲突项默认跳过，不能覆盖。
6. 优先尝试同一存储中的安全重命名；不支持时使用“复制到目标临时位置 → 校验 → 正式落盘 → 删除源文件”。
7. 数据库事务中保留原章节 ID；只有目标已存在可确认的重复数据库记录时，才合并历史和其他 ID 关联资料。
8. 移动成功后保留原篇目的阅读进度、已读、书签、历史、译名、标记、备注、自定义封面和原文件形式（文件夹仍为文件夹，CBZ 仍为 CBZ）。
9. 只刷新来源和目标条目；底栏显示移动进度，大批量或耗时操作退到后台后继续通过通知栏显示。
10. 如果来源条目已经没有任何篇目，不在本库列表中显示。只清理确认为空的物理目录；数据库中的漫画身份和漫画级资料保留，但导入/移动目标选择页过滤无篇目条目，避免它们继续参与日常操作。

### 篇目 ID 规则

- **详情页导入的新篇目**：目标漫画 ID 直接使用当前详情页对应的 `mangaId`；文件成功落盘并完成扫描确认后，在章节数据库中创建一条新记录，由 SQLite/现有章节仓库生成当前数据库记录中的唯一 `chapterId`。这个 ID 与文件夹名、CBZ 文件名和目标路径无关，后续改名或移动仍应继续保留。
- **本库已有篇目的详情页移动**：不创建新篇目 ID，沿用原 `chapterId`，只更新 `mangaId` 和篇目 URL；因此进度、已读、书签、历史、译名壳、备注、标记和自定义篇目封面继续跟随原篇目。
- **导入外部 Mihon 目录/归档**：即使文件格式和目录结构完全符合 Mihon，也没有本应用数据库中的原始 `chapterId`，所以按“新篇目”处理，不能仅凭文件名恢复外部阅读进度。
- **目标已存在同名篇目**：默认跳过，不产生第二个 ID；只有本库已有篇目移动且目标存在对应数据库重复记录时，才进入现有的事务合并流程，保留一个主 `chapterId` 并合并可迁移的章节级资料。
- **文件格式转换**：图片文件夹打包为 CBZ 时仍只创建一个新的篇目 ID；转换不是先创建文件夹篇目再创建 CBZ 篇目。

#### 详情页移动的交互约定

- 单篇和多篇共用同一个“移动到…”入口，不再额外增加顶级按钮。
- “移动到…”作为本地源多选底栏中的直接可见操作，使用明确的文件移动图标，不隐藏到页面顶层菜单中；同时调整底栏的操作收纳和稳定尺寸，避免新增按钮后图标或文字被挤压。
- 目标选择页优先展示最近使用的目标，其余条目按当前本库排序；搜索只在现有内存快照中完成，不触发全库扫描。
- 同一目标条目同一时间只允许一个导入/移动任务写入，避免两个任务同时创建同名篇目或交错刷新索引。
- 移动使用篇目当前文件名，不自动改名、不改变内部图片名称或排序。
- 移动后完全服从目标条目的现有排序：目标按名称、日期、篇目号等排序时自然重新排列，不人为保留来源位置；只有目标采用自定义排序时，才把移动篇目追加到末尾，并在这些新增项之间保留来源中的相对顺序。
- 同一批中无冲突的篇目可以继续移动；冲突篇目单独跳过并留在原条目中。
- 目标在确认后出现新的同名文件时，落盘前再次检查并跳过，不能覆盖。
- 移动失败或取消时，尚未完成的篇目留在来源；已经完整成功的篇目保留在目标，不做可能再次失败的批量反向移动。
- 操作完成后显示简短汇总，例如“已移动 8，跳过 2，失败 1”；无须弹出逐篇成功提示。
- 移入已有目标条目时不自动替换其漫画封面；新建目标条目使用第一篇成功移入内容的封面作为默认候选。
- 来源条目的用户自定义漫画封面保持不变；如果来源使用的是自动派生封面且对应篇目已移走，则只为来源条目重新选择有效的自动封面。
- 漫画条目级资料（漫画自定义封面、条目备注、分类、跟踪/同步信息和漫画级元数据）不自动覆盖目标，也不因为篇目移动而盲目复制；只有在来源条目被安全清理且用户明确选择时，才讨论单独迁移。

## 技术实现边界

- 复用 [`LocalSourceFileSystem.kt`](../source-local/src/main/kotlin/tachiyomi/source/local/io/LocalSourceFileSystem.kt) 的本地文件访问和 SAF 兼容逻辑。
- 为导入和详情页移动建立共用的本地篇目传输服务，避免两套不同的冲突和回滚规则。
- 复用现有 `mihon.core.archive.ZipWriter` 生成 CBZ，不引入外部压缩应用；扩展写入回调以报告逐文件/逐字节进度。
- 复用本地源已有的自然页面排序比较器，文件夹和 CBZ 的阅读顺序采用相同语义，且不改写原文件名。
- 使用可恢复的前台 `WorkManager` 任务承载长时间导入，并使用独立的低打扰通知渠道展示进度和取消操作。
- 通知栏遵循现有“隐藏通知内容”安全偏好；开启隐藏时只显示“正在导入本地本子”和数量/进度，不显示来源路径、漫画名或篇目名。
- 选择外部 SAF 来源后立即申请并验证可持久化 URI 权限；提供器不支持持久权限时，任务不能承诺在进程被回收后继续，应在开始前提示用户并限制为当前会话可完成的任务。
- 目标文件使用临时名称写入，校验成功后再提升为正式名称。
- 文件操作成功与数据库更新之间采用可补偿顺序；任何失败都不能先删除唯一源文件。
- 为每个本子保存独立任务状态（待处理、复制中、已校验、已提交、源已清理、失败），逐本恢复和重试，避免大批量任务要求同时保留全部副本。
- 复用现有 `relocateAll()` / `mergeRelocatedChapter()`，保留稳定章节 ID。
- 迁移或合并时审计历史、书签、阅读进度、译名壳、标记、篇目备注、自定义章节封面和备份恢复引用。章节 ID 不变时，这些数据继续指向同一篇目；目标已有重复记录时，在同一数据库事务中合并后再清理重复 ID 的引用。
- 新导入的外部文件没有既有章节数据库 ID，因此默认作为新篇目创建，不能凭文件名伪造或继承外部阅读进度；只有从本库现有篇目执行移动，才承诺完整保留章节级持久化数据。
- `ChapterRepository.addAll()`/`insertReturningId` 是新篇目 ID 的唯一生成入口；导入服务不得自行编造负数、文件哈希或路径派生的伪 ID。
- 文件提交、章节数据库迁移、封面缓存迁移、源文件清理和空目录清理必须按可补偿顺序执行；任何一步失败都不能先删除唯一来源，也不能删除仍被章节或用户资料引用的数据库行。
- 文件系统与 SQLite 不能组成真正的跨系统原子事务，因此不承诺断电瞬间“全有或全无”；使用任务日志/状态机实现两阶段提交和恢复。允许短暂出现“源与目标都存在”或“目标已提交、源待清理”，不允许出现“源已删除、目标未完整提交”或“数据库已指向不存在文件”。
- 导入完成后只失效来源、目标条目的目录签名、篇目索引、页数缓存和封面缓存，不触发无关全库扫描。
- SAF 暂时返回“可访问但为空”时，保留最后一次可靠索引和界面结果，不能把它当成确认删除。

## 风险与验证

- 同一篇目同时存在文件夹和 CBZ 时，必须避免误判为两个不同篇目。
- 同名但内容不同不能静默覆盖。
- 来源删除失败时不能报告为“已移动完成”。
- 应用崩溃或取消后，临时文件必须可清理，已完成项目不能破坏。
- 前后台切换、进程被系统回收和设备重启后，不能重复删除源文件或把未完成临时文件公开为正式篇目。
- 设备重启或 SAF 权限失效后，任务应进入“需要重新授权/暂停”状态，而不是无限重试或删除来源。
- 验证 40GB 级批量任务的峰值额外存储占用只与当前单本相关，并覆盖逐本删除后中断、重启和继续执行的场景。
- CBZ 写入顺序与文件夹阅读顺序必须一致，并覆盖纯数字、数字加文字、大小写和非 ASCII 文件名测试。
- 大型本库中不能为了导入而重新扫描全部漫画、重新打开全部压缩包或重新生成全部封面。
- 需要验证冷启动、重新进入、筛选计数、随机选择、阅读进度、历史、书签、译名、标记、自定义封面和备份恢复。
- 需要专门验证“移动后章节级数据仍在、漫画级数据不被覆盖”：已读/进度/书签/历史/译名壳/标记/篇目备注/自定义篇目封面必须继续存在；目标漫画封面、目标备注、分类和其他条目级资料必须保持原样。
- 设备验收时严格排除已知的 3 个非法 UTF-8 异常条目，不把它们计入目录统计或差异判断。

## 暂定决策

- 第一阶段的冲突处理只提供默认跳过，不提供覆盖；“保留为新名称”留作可选扩展。
- 导入预览显示名称、图片数、文件大小和明显异常；不为了预览封面或页数而提前打开所有大归档，也不在开始前逐张计算内容哈希。
- 复制/打包时边读边统计字节数和文件清单；目标提交前只做必要的结构复核，避免为了“校验”把 40GB 内容无意义地完整读取两遍。
- 取消只在当前本子的安全边界生效：正在写入时可停止并清理临时目标；目标已正式提交后，即使用户立刻取消，也必须完成数据库状态和来源清理决策，不能留下“目标已存在但任务状态未知”的半状态。
- “导入成功后删除源文件”不提供虚假的撤销按钮，因为外部文件删除后无法可靠恢复；删除前依靠明确选项、完整复制校验和最终状态检查保证安全。
- CBZ 只收入支持的图片、明确封面和 Mihon 可识别的元数据。检测到其他未迁移附件时可以完成导入，但不自动删除原目录，并在结果中说明原因。

- 来源选择会先做轻量展开预览，只把能识别出图片目录或支持归档的来源加入列表；页面显示来源名、将导入的本子数量和部分本子名，XML、`.nomedia`、普通文档等无关项会明确显示为已忽略。
- 选择的文件夹内若直接包含支持的单本归档，也会作为有效来源识别；同时保留“根目录直接图片优先、混杂无关文件忽略”的规则。
- 导入确认前会执行轻量同名预览；目标已有条目或本次选择内部重复时弹出提示，继续后仍默认跳过冲突且不覆盖源文件。
- 本地篇目封面生成统一优先使用直接命名为 `cover.jpg` 的图片；该图片仍保留在篇目目录或 CBZ 内容中，只额外生成封面缓存。
- 取消信号不会被传输服务吞掉；当前篇目的临时目标会清理，未完成来源保留。
- 目录篇目移动和成功后删除源均采用递归删除；复制/打包过程中任何子项无法创建都会使当前篇目失败并清理临时目标，不会把半成品登记为正式篇目。
- CBZ 模式遇到未迁移附件时保留源目录，不把“成功导入图片”误当成“可以安全删除整个源目录”；进度总量只统计实际迁移的内容。
- 篇目移动完成后，只有确认来源没有剩余篇目且目录只剩空目录标记时，才清理来源空目录；空漫画数据库身份保留，但普通本库和目标选择器会过滤无篇目的条目。

- 原生移动在数据库更新或任务取消后带补偿回滚，避免文件位置已变更但篇目身份仍停留在来源合集的半完成状态。

- 来源入口统一为“从文件夹导入本子”和“导入单本漫画压缩包”，已添加来源可逐项移除；导入选项和进度放入同一页面的轻量分区卡片中。

- 同一目标漫画的导入/移动任务串行执行；不同目标可以排队，默认不做无界并发复制，避免 SAF 和存储 I/O 抢占阅读器。
- 任务完成后只刷新来源、目标、章节索引和相关封面缓存；不打开无关漫画的归档、不重建全库封面。
- 新篇目创建失败时保留已验证的目标临时文件供任务恢复或清理，不能留下看似正常但数据库没有记录的正式篇目。
- 备份/恢复必须把新篇目的 `chapterId`、移动后的原 `chapterId` 以及章节级持久化资料按现有数据库语义处理，不把文件路径当作身份。
- 交付验收重点覆盖：详情页导入、批量导入、跨作者移动、目标重名、逐本删除、任务取消/重启、SAF 权限失效、40GB 级空间峰值，以及进度/封面/译名壳/历史/书签的持久化。
