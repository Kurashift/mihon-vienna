# Mihon Vienna 2.3.1

> 音频播放界面重做：进度条和音量条不再是 Material 默认的粗条，播放起步也不再等网络。**另外这一版换了签名密钥，升级前请务必先备份，见下方红字。**

---

## 🔴 升级前必读：需要先卸载再安装

**这一版换了签名密钥，无法覆盖安装。**

原来的签名密钥文件丢失且无法找回，所以从这个版本开始用新密钥签名。Android 规定：新包的签名必须和已装版本完全一致才允许覆盖升级，签名不同会被直接拒绝。

**这意味着：直接安装会失败，必须先卸载旧版。而卸载会清空应用数据。**

请按这个顺序操作：

| 步骤 | 操作 |
|---|---|
| 1️⃣ **先备份** | 打开旧版 → **设置 → 数据与存储 → 创建备份**，记下备份文件的保存位置 |
| 2️⃣ 卸载 | 在系统里卸载 Mihon Vienna |
| 3️⃣ 安装 | 装这一版 APK |
| 4️⃣ 恢复 | 打开新版 → **设置 → 数据与存储 → 从备份恢复**，选第 1 步那个文件 |

**关于数据**：

- ✅ **漫画文件、下载内容不会丢**。它们在公共存储里，卸载应用不会删除，重新导入或重新指定目录即可
- ✅ **阅读进度、已读标记、书签、书架分类能恢复**，只要第 1 步备份成功
- ⚠️ **音频模块的播放历史、播放列表、本地收藏恢复不了**。备份格式只覆盖漫画数据，不含音频。账号相关的收藏状态重新登录后可以同步回来，本地记录不行

> 💡 只要你之后保管好新的密钥文件，**从这一版往后都能正常覆盖升级**，不会再遇到这个问题。

## 🎚 播放界面：进度条和音量条重做

以前这两条用的是 Material 的默认样式 —— 16dp 厚的轨道上放一根 4×44dp 的竖条滑块，**滑块比轨道还窄，当前位置根本读不出来**。现在改成：

**进度条**（一条细线）

- 轨道 4dp，全圆角
- 三段颜色：已播（主题色）→ **已缓冲**（浅灰）→ 未播（更浅）
- 滑块是一个圆点，外面套一圈和背景同色的环，让它明确「浮」在轨道上
- 按住拖动时圆点会略微放大，能看出正在拖

**缓冲段是这一版新增的**：播放器其实一直在报告缓冲位置，只是以前没有任何地方把它画出来，所以进度条只能告诉你「播到哪了」，说不了「读到哪了」。

**音量条**（一排细虚线）

和进度条**故意做成不同形状** —— 两者回答的问题不一样：进度是「在时间轴的哪个位置」，音量是「15 档里的第几档」。以前两条长得一模一样，扫一眼分不清哪个是哪个。

- 填了几格就是几档，**数格子就知道音量**，不需要知道满档是多少
- 调到 0（静音）时所有格子都空着，但格子框还在 —— 以前滑块会整个消失，看起来像坏了

## ⚡ 播放起步不再等网络

以前每次点播放，都要**先联网解析一次音轨地址**才会开始播。这一步本身是必要的（存的地址可能早于你当前的音质设置），但让它变便宜的唯一手段是 5 分钟的 HTTP 缓存 —— 偏偏在你**从历史记录或播放列表点开一首几小时没听的曲子**时正好过期。

现在音轨树存在内存里，解析从「一次网络请求」变成「一次内存查找」。

顺带说明：**不是网站慢**。实测后端接口约 336ms、媒体 CDN 首字节约 120ms、下载速度 5–9 MB/s，一直都不慢。慢的是这一步被强制串在播放之前。

**同时修了一个连带问题**：解析结果现在可能最多旧 30 分钟，万一地址真的失效了，以前会被当成不可重试的错误**直接跳到下一首**（你想听第 3 首，它播了第 4 首）。现在会丢弃缓存、重新解析一次、原地续播。

**另外**：媒体数据不再占用 JSON 缓存。CDN 对音频返回 4 小时缓存头，那 20 MiB 的缓存一直在收集几十 MB 的音频，把本该给它缓存的作品列表和音轨树挤出去。

## 🔧 其他修复

- **长按作品标题不再误选篇目**。网格的长按判定把「按下」当成了「拖动」，用拖动才该有的「就近吸附」去解析手指位置，于是按在标题、简介、篇目标题栏上都会选中离得最近的那个篇目。现在按下必须真的落在卡片上才算
- **删除本地作品不再被「文件已不在」挡住**。以前文件缺失被当成错误，导致文件夹部分丢失的作品根本删不掉，计数和列表也一直和磁盘对不上
