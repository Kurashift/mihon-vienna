# 文案风格

管这些文件里的中文（和英文）：

- `README.md`
- `docs/release-post-*.md`（发布正文）
- `CHANGELOG.md` 里 fork 自己的段落
- 提交信息

不管 `i18n/**/strings.xml` 的界面文案——那些受长度、占位符和既有口吻约束，按 UI 文案自己的规矩改（见历次 i18n 提交）。

判断一句话要不要留，先问：**删掉它，信息少了吗？** 没少就是填充。

---

## 一、已经在做对的事，别丢

**写具体的东西。** 「一本 22 页的书读到第 2 页，却显示 `1/2`；读到第 1 页显示 `0/1`」比「进度显示异常」有用得多。数字、条数、上限、设备名，能写就写。

**先说读者看到什么，再说为什么。** 「以前一个文件读不了，整部作品的篇目列表都建不出来」是现象，「格式探测没有兜底」是原因。顺序别倒。

**用「以前……现在……」讲改动。** 这是发布正文里出现最多也最有效的句式，读的人一眼知道自己会不会受益。

**解释动机时给真实理由。** 2.1.4 每节末尾的「为什么要这样？」是好东西，因为理由具体（「一堆罗马音或日语确实看不懂含义」）。理由不具体时（「为了提升体验」），这个标题就变成了凑数。

**保留作者口吻。** 「短篇本子最耗神的从来不是看，是挑」「不留半截尸体在界面上」「一个红色垃圾桶摆在书架操作旁边，很容易被理解成「移出书架」」——这是本人在说话。不要改成中性表述。

---

## 二、不要写

### 替读者下判断

「真」「其实」「实际上」用在标题或引导句里，多半是在替读者强调。

- `顺带修了三个真问题：` → `顺带修了三处：`，或直接列
- `随机，真的会用到全部结果` → 标题说结论，不喊口号

### 空引导句

一行以冒号结尾、内容全在下面的句子，只有它自己提供信息时才留。

- `几个要点：` / `几个细节：` → 删，直接列
- `现在随机的范围是整个筛选结果：` → 留，这句本身是结论
- `以前……现在：` 这种前后对照的过渡句留，它交代了变化方向

「以前……现在」是本仓库用得最多也最有效的句式，不要为了精简把「现在」砍掉。

### 拔高

删掉没有独立信息的自我评价。

- `这是本项目最核心的能力。目标很直接：不想选了，一键「看缘分」。` → `目标很直接：不想选了，一键「看缘分」。`
- `这是体验上最有辨识度的部分。` → 删
- `跳转细节也一一打磨过：` → `跳转细节：`

### 装饰

**标题 emoji。** 一篇里超过一半的标题都带 emoji，它就不再起区分作用。只给需要单独跳读的那一两节加，或者不加（2.3.2 就是不加的样子）。

**破折号。** 本仓库的用法是稳定的：「**粗体条目** —— 解释」。这是承担解释功能的破折号，保留，不要为了精简改成句号。要改的只有拿它制造悬念或掩盖分句关系的那种（`结果终于出来了——答案是导出失败`）。

## 三、三类必须写在最前面的改动

1. **要卸载重装的**（签名变更这类）
2. **会动用户数据的**（重排排序、修正历史数据、迁移）
3. **修的是数据损坏类 bug**

这三类埋在列表里等于没写。2.3.1 和 2.3.2 的开头处理得对，照这个来。

## 四、发布正文的骨架

```markdown
# Mihon Vienna <版本号>

> 一句话说这版是什么（可选，小版本可以省）

<需要读者先知道的事：卸载重装、数据修正、备份提醒>

---

## <分节标题>

……

---

## 下载哪个包

| 文件 | 用途 |
| --- | --- |
| `MihonVienna-<版本>-arm64-v8a.apk` | 手机 / 平板，绝大多数设备选这个 |
| `MihonVienna-<版本>-x86_64.apk` | 安卓模拟器 |
| `MihonVienna-<版本>-armeabi-v7a.apk` | 老旧 32 位设备 |
| `MihonVienna-<版本>-universal.apk` | 全架构，体积最大 |
```

- 一级标题会被 `scripts/publish_release.py` 剥掉，Release 页面自带版本号。
- 下载表四行都要写，ABI 说明见 `AGENTS.md`。
- 正文从实际改动里写，不要照抄会话记录或提交信息。
- 论坛版（BBCode）从同一份正文转，不要另写一份。

---

## 五、写完自检

1. 删掉一个句子，信息少了吗？没少就是填充。
2. 每个数字、条数、上限，能不能在代码或提交里找到出处？
3. 有没有把「可能」写成「确定」，把「计划」写成「已经做了」？
4. 读者看完知道自己要不要升级、要不要先备份吗？
5. 有没有句子在替读者说「这个很重要」？
