# Vienna 更新与优化路线

以 Vienna 当前界面、阅读规则和操作手感为基准，吸收上游正式版中有明确收益的改动。每批独立分支、独立 PR；不升版本，不发布 APK。

## 保留的行为

- 条漫滑动、惯性、双指缩放、双击、横屏和随机切换手势。
- 图片提前定高、首帧对齐、跨篇目防跳位、相邻篇目预载和拖进度条后的接续。
- 跳过已读、完成阅读判定、续读位置与进度保护。
- 本地库缓存优先显示，以及稳定 ID、译名、标记、书签、自定义排序和封面。
- 现有菜单和入口；普通操作不增加提示、加载页或确认弹窗。

## 推进顺序

| 批次 | 内容 | 状态 |
| --- | --- | --- |
| 1 | 阅读记录计时快照、按序保存、离开页面后完成已确认写入 | 本地检查、单测、迁移校验与 Vienna 编译通过；真机待验 |
| 2 | 漫画详情页隐藏 5 秒后暂停查询与列表整理，返回时接收最新状态 | 本地检查、单测、迁移校验与 Vienna 编译通过；真机待验 |
| 3 | 章节新增、修改、删除同事务提交，下载改名失败时补偿 | 本地检查、单测、迁移校验、SQLite 大库验证与 Vienna 编译通过；真机待验 |
| 4 | 扩展安装与更新：仓库、签名、取消与保留旧扩展 | 前三批完成后评估 |
| 5 | 下载重启与索引、缓存一致性 | 第四批后评估 |
| 6 | 冷启动、返回页面、大库筛选与批量操作的基线及优化 | 第五批后评估 |

后续每批先核对上游正式版与 Vienna 已有实现。性能验证包含 3,000 部以上作品和大量篇目，不能只凭小样本采用优化。

条漫图片分块、整库结构迁移、整套阅读器重写、WebGPU 和全面依赖注入迁移不在本轮范围。网络整章预加载、ComicInfo 日期和章节识别排在本地阅读可靠性之后。条漫分块须同设备同素材证明收益，不能增加白块、可见等待、跳位或降低放大清晰度。

## 第一批：阅读记录保存

以前异步保存等待进度写入后才读取计时，两个保存可能累计同一段时长；旧任务完成时也可能清掉下一段计时。现在保存请求同步固定篇目、结束时间和时长，并取走计时，再依次执行进度与历史写入。退出阅读器不取消已确认的保存；写入期间保留所需篇目资源，结束后释放。切换篇目的保存统一放在当前篇目更换之前，覆盖连续翻页和工具栏切章。

没有新增界面。滑动、缩放、预载与完成阅读规则不作调整。自动测试负责计时和并发，不要求观察秒数。

### 手动回归

1. 从作品详情打开一部至少有三个篇目的测试漫画，在第一篇连续下滑数页，再反向翻回。预期没有白块、跳位或异常已读。
2. 继续跨到第二篇，再切到第三篇；另试一次工具栏前后篇按钮。预期篇目和页码对应当前内容。
3. 拖进度条到中间，双指缩放后恢复，立即退出阅读器并重新进入。预期续读位置与已确认停留位置一致，未读篇目不会意外变已读。
4. 查看历史，应显示刚读过的篇目；再进入隐身模式读一个不同篇目、退出。预期隐身阅读不新增历史。

白块、跳位、错误已读、续读位置倒退、历史串篇目均算回归。准确计时、重叠保存、旧任务与新计时隔离、隐身跳过保存及失败后后续保存继续由自动测试覆盖。真机手感、页面状态和崩溃日志仍待安装后由用户操作验收。

## 第二批：详情页隐藏期间的工作

只对漫画详情页启用订阅门控。隐藏超过 5 秒后暂停重复查询与列表整理，返回时保留旧页面并接收最新状态；删除完成通知与实际写入继续执行。实现范围、自动验证和四步手动回归见 [详情页订阅回归](detail-subscription-regression.md)。

## 第三批：章节刷新事务

新增、修改和删除统一提交或回滚，更新只写来源字段。下载改名记录回执，失败时反向补偿并同步缓存，不删除文件。实现范围、真实 SQLite 大库验证和五步手动回归见 [章节刷新回归](chapter-sync-regression.md)。

## 固定验证要求

前三批真机回归期间发现的条漫双击缩放问题，先按 [缩放回归说明](reader-zoom-regression.md) 修复并验收。该修复不推进图片分块或阅读器重写。完成本轮回归后再开展第四批。

每批先执行 spotlessCheck、testDebugUnitTest、verifySqlDelightMigration，再执行 :app:compileViennaKotlin。测试通过后提交、推送并开 squash auto-merge PR，立即报告本地结果与待验项目。

跨模块改动前后核对共享调用方。缓存与保护逻辑同时覆盖正常新增、删除、批量移动、目录改名、冷启动和缓存恢复。文件操作只使用测试副本；不通过清数据、撤销权限、重建主库或制造真实文件损坏完成验收。
